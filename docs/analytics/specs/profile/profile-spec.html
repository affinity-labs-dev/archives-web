Analysis Notes

  • Privacy Policy and FAQ are stubs: The handlePrivacyPolicy and handleFAQ callbacks in useProfileAccount.ts only log to console — no URL is opened. These need real implementation before analytics wiring.
  • Avatar picker is a no-op: handleOpenAvatarPicker in profile.tsx is an empty callback — the avatar edit button exists in the UI but does nothing on tap.
  • No profile-specific analytics exist today: The only wired events are the generic page_view (from startPageView/endPageView), user_session_out, and user_account_deleted. Every interaction within the profile (settings toggles, achievement/badge browsing, stat expansion) is completely untracked.
  • Sign out has two redirect paths: If the user has a remembered account snapshot (userId + email), they redirect to /welcome-back. Otherwise they redirect to /onboarding-step-1. Tracking which path fires would reveal how many sign-outs are account-switches versus full logouts.
  • Delete account computes analytics before deletion: The user_account_deleted event fires before user.delete() is called, which is correct — if it fired after, the PostHog user would already be reset. However, if the deletion fails, the event has already been sent (false positive).
  • manualSignOutInProgress flag: Both sign-out and delete-account set analyticsService.manualSignOutInProgress = true to prevent the duplicate clerk_session_ended event from _layout.tsx. If this flag is not properly reset, subsequent auth state changes would be missed.
